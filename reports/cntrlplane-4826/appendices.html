Scope and limitations

Live runs used upstream CAPI manager images. The downstream CAPI rebase in the HyperShift fork was not exercised. A second provider and InPlace were not executed; T8 records their scope dispositions. The no-current-MachineSet branch at zero desired replicas is covered by unit tests only.

Sanitization

  • The guest kubeconfig and the management kubeconfig are not included in this bundle.
  • Azure subscription, tenant and principal identifiers are replaced with stable redaction tokens.
  • Private domains, load-balancer hostnames, secret data and bearer values are replaced.
  • Names of test resources are normalized; image registries are normalized to quay.io/example/.
  • Original SHA-256 manifests are retained under assets/provenance/original-checksum-manifests/ with an invalidation suffix because sanitization changed their inputs. Verify published bytes using SANITIZED-SHA256SUMS.

Reproduction

  1. Build base ee327075b1 and head ee5691233b with podman build -f ./Dockerfile.dev --platform=linux/amd64 and push both images.
  2. Create an Azure self-managed HostedCluster with the CAPI manager overridden with the annotation hypershift.openshift.io/capi-manager-image. Use registry.k8s.io/cluster-api/cluster-api-controller:v1.14.3 for T1–T7 and v1.13.4 for T8.
  3. Run run-t1.sh baseline with the base image and run-t1.sh patched with the head image. Both scripts snapshot before state, patch release B, sample every 5 s, require an explicit PASS/FAIL and archive operator logs and events.
  4. For the pre-1.14 row, run run-t1.sh patched against the 1.13.4 manager and evaluate its trace with verify-t8.sh, because the stock runner encodes the 1.14 stall signature as its success gate.
